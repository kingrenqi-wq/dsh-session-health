> 版本：v2.2 · 2026-10-30 · 根据评审修订，M0 待验证  
> 定位：本地会话状态与异常证据插件。  
> 本文作为新版实施依据；原《PRD-DSH会话健康插件.md》保留为历史方案。

本版已按用户授权采纳评审中必要的恢复与边界规则；评审文档里的角色推演不视为团队批准。M0 未完成，本文不表示插件能力已验证或允许对外发布。v2.1 保留在上一版讨论包中。

| v2.1 | 跨目标失败计数、token 恒等式、默认待确认、疲劳指标、帧推进与快照淡化 |

术语：轮次指宿主 turn；请求代次用于丢弃过期响应；文件代次指源文件一次连续有效生命周期；宿主运行周期指可被证实的宿主实例生命周期。三种代次不能互相替代。快照是最近一次有效请求用量；提示实例是一次从触发到退出当前提示的展示过程，不等于任务本身。

## 1. 产品目标

在会话标题栏显示最近一次可确认的上下文占用；发生连续工具失败或任务长时间未结束时，给出简短提示，点击可查看证据。

帮助用户回答三个具体问题：

1. 最近一次模型请求使用了多少上下文？
2. 是否有需要我查看的连续失败或长时间未结束任务？
3. 提示来自哪条记录，问题现在是否已经解除？

不承诺判断任务是否走歪、回答是否正确、任务是否完成，也不预测还能工作多少分钟。产品命名采用“会话状态”，避免将有限信号包装成全面的健康判断。

## 2. 首版范围

| 纳入 v1 | 具体内容 |
|---|---|
| 上下文占用 | 最近一次已完成请求的输入 token / 对应请求的上下文窗口；显示采样时间 |
| 连续失败提示 | 同一轮、同一工具连续出现两次同类明确失败，跨目标合并计数 |
| 长时间任务提示 | 单个任务已开始至少 300 秒且未见终态；默认待确认，有存活确认才显示运行时长；缺乏新证据的旧提示按 §6.2 转历史 |
| 证据浮层 | 原因、发生时间、任务或工具名称、轮次、seq、当前是否解除 |
| 异常降级 | 数据不可用时说明原因；部分数据缺失时保留可确认的信息 |
| 插件生命周期 | 会话切换、启停、卸载、主题适配和资源清理 |

不纳入 v1：ETA、预计剩余步数、自动学习压缩阈值、65% 高位告警、健康评分、费用、跨会话排行、子代理独立会话统计、联网服务、自动重试或终止任务、会话位置跳转。

300 秒和两次失败是首版待验证的产品阈值，不能表述为已证明有效的异常边界。原方案的 20 个会话 / 533 轮及三个压缩样本只作为探索线索，不作为新版准确率依据。

## 3. 核心场景与文案

| 场景 | 标题栏示例 | 点击后说明 |
|---|---|---|
| 数据可用，无当前提示 | `上下文 41%` | 最近请求时间；“未检测到连续失败或长时间未结束任务” |
| 连续失败 | `上下文 41% · 同类失败 ×2` | 工具名、失败类别、记录数、目标数及每条证据的时间 |
| 无任务存活查询能力（默认档） | `上下文 41% · 任务状态待确认` | “任务开始于 13:40，尚未找到结束记录”；达到 300 秒才提示，不称为仍在运行 |
| 确认仍在运行的长任务（可选档） | `上下文 41% · 任务已运行 5 分钟` | 仅在 M0 确认具备存活查询且取得有效确认后显示 |
| 上下文未知，但失败证据有效 | `上下文未知 · 同类失败 ×2` | 分别说明上下文缺失与失败证据 |
| 无当前会话 | 不显示 | 无 |
| 当前会话数据不可读 | `状态不可用` | 文件不可读、格式不支持等具体原因 |

正常状态使用中性色；有当前提示使用黄色，同时必须有文字原因。不得出现“一切正常”“任务卡死”“即将撑爆”等超出证据的结论。

## 4. 数据契约与前置验证

### 4.1 原则

仅访问当前工作区主会话的本地数据。以宿主提供的当前会话身份映射文件，不接受界面传入任意文件路径。会话切换后不得显示上一会话的数据。

现有线索是 `~/.dsh/sessions/<workspace>/<id>/session.v4.jsonl.zstd`。事件名、字段名及通信 API 均需在 M0 根据当前安装版本核实；下表是需要的数据语义，不是对未验证接口的保证。

| 数据 | 候选来源 | M0 必须确认 |
|---|---|---|
| 当前会话 | 宿主会话上下文 | 工作区与 sessionId 的映射，主会话边界 |
| 输入用量 | `assistant/message` 的 usage | 在目标版本重跑 §4.2 恒等式自检，并确认单次请求关联关系 |
| 上下文窗口 | `request/context` | 与输入用量属于同一请求、同一模型配置 |
| 工具结果 | `tool/result` | toolCallId、操作身份、结构化成功/失败/取消状态 |
| 任务生命周期 | 开始/运行记录或宿主任务查询；`job/settled` | jobId、开始时间、终态；明确结论“有/没有存活查询”，有则验证确认有效期及重启语义 |
| 轮次边界 | `turn/start`、`turn/end` | turnId 以及中断、异常退出的表示方式 |
| 压缩边界 | 压缩开始与完成/失败记录 | 压缩期间如何使旧占用值失效，何时能重新采样 |
| 证据定位 | 时间、seq、关联 ID | 顺序、去重、缺失字段时的处理 |

### 4.2 数据可信边界

- 本机 token 口径已核实（用户提供的实测结果）：4075 条 usage 事件全部满足 `totalTokens = inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`，0 例不符。输入上下文占用取 `totalTokens − outputTokens`，等价于三项输入之和，不单独取 `inputTokens`。该结论限于已检查的本机版本与样本，不外推到其他版本。
- 上线前口径验证：在目标版本重跑同一恒等式，保存版本、样本清单、检查总数、字段缺失数和不符数。完整样本数须大于零，所有计数字段为非负安全整数且逐条等式成立，字段缺失不擅自补零；失败则不启用对应的未验证口径，显示“上下文未知”。该自检不替代请求与窗口的关联验证。
- 运行时单条校验：已验证口径下，一条 usage 缺字段或等式不成立，仅使对应会话的该请求快照未知，不关闭其他会话，也不用更早的正确记录冒充当前快照。后续新的完整 usage 自检通过并正确关联当前模型、窗口时，自动恢复该会话的占用展示。
- 口径变更：宿主版本、事件格式或已登记的模型/provider 适配范围变化时，回到该口径的上线前验证；一条新记录通过等式不能替代整项能力验证。其他已验证且不依赖该口径的能力继续工作。
- 本机示例中 `inputTokens = 1854`、`cacheReadTokens = 8832`；按该样本窗口，单取前者约为 0.18%，计入缓存后约为 1.02%，相差约 5.7 倍。本轮未独立复算原始样本。
- 失败优先使用结构化状态。文本匹配只允许针对已验证的工具输出格式；普通正文里出现 `Error:`、代码示例或错误日志，不自动等于工具调用失败。
- 非零退出码不一概等于异常。例如搜索无匹配可能是正常结果；按工具语义解释，无法确定时记为未知，不计入失败连击。
- 取消与失败分开；只有明确的取消状态才归类为取消，不能仅凭 `aborted` 推断一定是用户按 Esc。
- 同一调用的工具结果与任务结束事件关联后去重，不能把一次失败计成两次。
- 只支持经过验证的格式。未来版本或关键字段变更时降级，不猜字段含义。

### 4.3 最小能力登记

M0 为每个能力保存：宿主版本、事件格式、能力名、适用模型/provider（无关时填不适用）、支持/不支持/待验证、验证日期、验证人、证据路径和失败时的降级。具体版本号必须实测回填，不能从历史交接文档推定当前环境。

| 能力 | 当前状态 | 证据 / 待核实内容 | 不支持或未验证时 |
|---|---|---|---|
| 宿主通信、取消/超时与有界执行 | 待验证 | 待 M0 验证通信、取消及有界执行路径 | 阻塞实时插件路径，记录替代路线后再评审 |
| 标题栏 slot、会话身份映射 | 待验证 | 待 M0 验证真实挂载与会话映射 | 不接错会话或私自换插入位置；M0 明确替代方案 |
| usage 口径及请求/窗口关联 | 待验证 | 用户报告本机 4075 条恒等式全部通过；目标版本登记、独立复验与请求关联待完成 | 对应口径显示上下文未知 |
| 工具结果、轮次、调用去重 | 待验证 | 待完整事件序列回放与去重验证 | 不启用相关工具的连续失败规则 |
| 任务开始/终态关联 | 待验证 | 待生命周期与实例关联验证 | 长任务能力不可用；仅占用率版本属于原型 |
| 存活查询、宿主运行周期 | 待验证 | 两项能力分别核实有/没有，并分别登记状态与证据 | 使用待确认档及旧提示退场规则 |
| zstd 解码、文件身份与事件顺序 | 待验证 | 格式方案已核对；目标运行时解码和文件行为待实测 | 解析不可用，不显示正常状态 |

状态列仅允许“支持”“不支持”“待验证”；用户报告、实测结果与限制写入证据列。升级后相关能力标为“待验证”（需复验），按登记的依赖局部降级。运行时的单条数据错误不等于兼容矩阵整体失效。矩阵随支持版本维护，不预填不存在的验证人或通过结果。

## 5. 上下文占用

### 5.1 计算与含义

`占用率 = (totalTokens − outputTokens) / 该请求对应的 contextWindow`

这是通过 §4.2 自检的最近一次请求快照，不是实时累加的计数器。不能跨消息求和，也不能将旧模型的用量除以新模型的窗口。v1 明确排除输出 token，计入缓存读写 token；浮层解释输入上下文占用口径。

标题栏显示整数百分比；大于零但不足 1% 显示 `<1%`。浮层显示 token 数、窗口值和“最近请求：时间”。输入缺失、窗口非正数或用量超出已验证的合理范围时显示“上下文未知”，不能简单截断数值掩盖问题。

### 5.2 更新与失效

| 事件 | 行为 |
|---|---|
| 新的完整请求用量到达 | 替换快照，更新时间 |
| 请求正在生成、尚无新 usage | 标题栏照旧显示百分比，不追加文字；仅浮层显示“上一请求数据 · 采样于 HH:MM” |
| 有效快照的采样时间距今超过 90 秒 | 仅标题栏占用数字降为 60% 不透明度，提示原因及状态点不变；浮层明确采样时间 |
| 新的有效快照到达且采样时间距今不超过 90 秒 | 恢复占用数字的默认不透明度；重新读取同一快照不能刷新采样时间 |
| 模型或窗口配置发生变化 | 旧快照不再作为当前占用展示；等待新配置对应的有效用量 |
| 自动或手动压缩开始 | 显示“上下文更新中”，不沿用压缩前数值 |
| 压缩完成或失败 | 等待后续有效请求快照；浮层显示已确认的压缩结果 |
| 无有效用量，但其他事件可读 | 仅上下文项显示未知，其他能力继续工作 |

生成中仍按真实快照年龄淡化，不暂停计时。淡化仅表示采样较早，不代表任务异常，不触发黄色；浮层解释“上一请求数据”。

快照年龄、任务阈值和提示展示期限采用统一时间策略：首次读取时用可信事件时间建立年龄基准，此后以单调时钟增量推进，重复读取不重置基准。墙上时钟用于显示事件时间；检测到明显跳变时保留可信单调基准，不能把负年龄当作新鲜。重启、休眠恢复或跨进程时不得直接比较旧的单调时钟数值，须重新建立基准；无法建立时标为“采样时间待确认”，数字保持淡化，停止依赖不可信年龄的新阈值判定。试用的可见时长从实际可见观察区间计量，同样使用可靠的单调增量，不从任务事件时间倒推；时间不可信的区间单列。M0 确认宿主事件时间单位、时钟来源及运行时的休眠计时语义。

占用高低本身不触发黄色。首版不假定 69% 一定压缩，也不为上下文余量解释剩余工作时间。

## 6. 两类提示规则

### 6.1 同类失败连续两次

判定范围为同一轮、同一工具的同类失败。**计数键 = 工具名 + 失败类别**；签名中去除目标、URL、主机名、路径等变量。目标仅用于浮层展示与目标数统计，不参与计数。连续两次即触发。

每个工具在当前轮维护一个连续失败序列；不同失败类别仍会中断该工具的旧连击，不把中间穿插其他结果的同类失败累计为“连续”。失败类别优先来自结构化错误；文本回退采用按工具验证的模板，只移除变量，保留错误类别差异，无法可靠分类时按未知结果处理。原始参数不直接展示或持久化。

本机实测依据（用户提供）：同一轮 `web_fetch` 对 8 个不同 URL 出现同类失败，包括 seq 204、205、216；签名不能因 `github.com` 与 `raw.githubusercontent.com` 等目标变化而拆开。完整序列仍需回放核验成功、取消或其他失败类别是否打断连击，不仅筛出失败行计数。

接受的代价是同一工具对不同文件各返回一次 ENOENT 也会合并提示。浮层按实际去重目标数显示“N 条记录 · M 个目标”（例如“8 条记录 · 3 个目标”）；目标按脱敏前的完整规范化目标在内存中去重，不只按域名统计，也不把不同目标的错误写成同一个目标反复失败。

| 后续记录 | 连击与提示变化 |
|---|---|
| 同一工具、同一失败类别再次失败，目标可不同 | 计数增加；到 2 次触发，之后更新同一提示及目标数 |
| 同一工具成功，目标可不同 | 清零；当前提示解除，历史标记“连击结束：后续调用成功”，不宣称此前失败目标已恢复 |
| 同一工具出现不同失败类别 | 原连击结束，从新类别的第 1 次开始；旧提示转历史 |
| 同一工具取消或结果未知 | 中断该工具的连击；旧提示转历史，标记“后续调用取消”或“后续状态未知”，不得标为成功 |
| assistant 文本、step 事件、其他工具结果 | 不影响本工具的连击 |
| 当前轮结束、中断，或开始新轮 | 清除该轮当前提示；保留历史，不宣称问题已修复 |

只根据完成的工具调用结果计算。并行调用以结果完成顺序处理；事件缺口导致连续性无法确认时重置相关连击并标明数据不完整。重复读取同一个事件不得重复计数。

### 6.2 长时间未结束的任务

首版阈值为 300 秒；未满阈值不触发。任务身份由会话身份、文件代次、可取得的宿主运行周期、jobId 与开始事件标识共同确定，不单独用 jobId 跨生命周期关联。

**若宿主不提供任务存活查询，本能力的默认输出就是“任务状态待确认”。** M0 必须给出明确结论：有 / 没有该能力，并据此决定是否提供“任务已运行 N 分钟”这一档；存活查询不是默认具备的前提。

本机实测依据（用户提供）：2957 次任务中超过 300 秒的 3 次，最终均为 killed；现有结论没有提供实时存活确认样本。终态 killed 本身不能证明任务在此前某时刻是否仍活着，验收必须按事件时间推进，不得拿最终状态倒推当时状态。

- 默认档：有可信开始时间、未见结束事件，但无存活查询能力或无有效确认，达到阈值后显示“任务状态待确认”；浮层陈述开始时间与缺少结束记录的事实，不显示持续运行计时。
- 可选档：M0 确认有查询能力，并在当次状态刷新中取得有效存活确认，才显示“任务已运行 N 分钟”。查询超时、失效或结果不明时回到默认档，不无限沿用过去的确认。
- 开始时间未知：不估算时长，不触发 300 秒规则。
- 成功、失败或取消的终态到达：立即解除当前长任务提示，历史证据记录终态。
- 轮次结束不自动等于后台任务结束；根据任务生命周期处理。宿主断连或重启后，未经重新确认的任务不得继续显示“运行中”。

**旧任务退场，不伪造终态：**

- 确认属于旧宿主运行周期、且重启后没有新的任务存活或生命周期证据时，转入“历史状态未确认”，不继续占用黄色。暂时断连、隐藏界面、切换会话或 turn/end 本身不构成宿主重启证据。
- 无法识别运行周期时，采用有限展示期限：从该任务最近一次可信生命周期事件（至少为开始事件）起，满 30 分钟仍无新证据则转为“历史状态未确认 · 长时间无新记录”。这是 v1 的提示展示默认值，不是任务结束或超时判定；M3 可复盘调整。轮询、读取相同日志、打开浮层、恢复可见和其他任务事件均不刷新该期限。
- 无可信时间基准且无法证明任务属于当前运行周期时，直接保留为历史未确认，不因无法计时而永久挂黄。后来取得可信基准或新的关联证据，再重新判定。
- 新的有效存活确认或生命周期证据可以重新建立当前提示，但仍须满足长任务阈值；新终态只更新历史，不重新挂黄。已持续取得存活确认的任务不受无新证据展示期限影响。
- 同一开始事件重读只去重；同一 jobId 出现不同开始事件时创建新任务实例，旧实例未结束则转历史未确认。迟到终态若不能可靠归属具体实例，不凭 jobId 猜测关闭新任务；记录关联不明并局部降级。

时间阈值每次轮询重新计算，即使文件没有新增字节。300 秒是“值得查看”的提示阈值，不是故障判定。计时遵循 §5.2；时间不可信时不新触发依赖年龄的黄色提示，已有未确认提示按上述规则转历史。

## 7. 状态、交互与证据

### 7.1 状态优先级

1. 无会话：不渲染。
2. 初次读取：显示“读取状态中”，不短暂显示正常。
3. 无法可靠读取当前会话：显示“状态不可用”；旧数据只可在浮层中带“上次成功读取”时间展示，不作为当前状态。
4. 数据可用或部分可用且有当前提示：黄色，标题栏展示原因。
5. 数据可用且无当前提示：中性色，展示上下文；不可用的单项显示未知。

部分能力不可用时，浮层必须列明，例如“任务状态暂不可用”。不能在该能力缺失时显示覆盖所有能力的“未发现异常”。

上下文项和提示项独立组合。压缩中无提示时显示中性色“上下文更新中”；同时有失败提示时显示黄色“上下文更新中 · 同类失败 ×2”，不能用压缩状态遮住原因。压缩结束尚无新 usage 时显示“上下文待采样”，浮层给出已确认的压缩结果。历史未确认记录不使标题栏变黄，也不意味着历史问题已经解决。

多个提示同时存在时，标题栏优先显示连续失败，其次是已确认的长任务，最后是任务状态待确认；同级按最近触发时间排序，末尾显示 `+N`，浮层列出全部当前提示。

### 7.2 浮层内容

由上到下依次为：

1. 上下文占用、口径、采样时间或不可用原因。
2. 当前提示：原因、工具/任务、发生时间、持续时间（可确认时）、证据。
3. 最近记录：已解除、已结束或转历史未确认的提示，显示退出当前提示的原因；无记录时显示空状态。

一条失败提示关联两次或更多失败事件，展示工具名、失败类别及“N 条记录 · M 个目标”，展开后逐条显示目标；一条长任务提示关联开始记录、最近状态及终态（如有）。每条证据显示轮次、时间和 seq；缺失字段明确显示不可用。v1 不提供尚未实现的“点击跳转”入口。

证据摘要采用可读的工具名、动作、脱敏目标和简短错误类别，不提供完整原始参数的展开入口。当前提示全部保留，列表按 20 条一页或等效的有界虚拟列表渲染；单条提示的目标与证据列表也每次最多渲染 20 条，显示总数与“加载更多”，摘要每条最多 200 字符。渲染上限不能改变总计数或静默丢失当前提示。

历史最多展示最近 50 条。重启后从源日志重建能够由日志确认的规则记录，标注“根据会话记录重建”；不能把离线重放推导出的提示当成当时确实展示过的提示，也不能重建日志中不存在的存活查询结果。历史与当前状态使用同一次有界、可取消的首读扫描，完成前显示“读取状态中/正在恢复记录”，不得暂时显示“无历史”。首读超时按 §8.2 降级，不额外发起并行全量扫描；不另存完整日志副本。

提示实例身份包含会话/文件代次、规则、关联实体、触发事件标识；同次提示的计数增长不换身份，退出后由新证据再次触发才创建新实例。基于时间触发的任务提示关联触发所依据的任务事件。实际展示实例与重建记录分开，只有实际观测的展示过程参与疲劳指标；未知触发或退出时刻的记录单列。

### 7.3 视觉与操作

- 首选位置为 `conversation.session.header.utilities`，是否可用由 M0 实测确认。
- 常驻控件目标高度 26px，正常态只展示占用；宽度不足时保留提示原因，详细数字进入浮层。
- 浮层目标宽度 352px，小窗口下自适应，长内容可滚动。
- 使用宿主主题 token；状态必须同时由文字表达，不能只靠颜色。
- 快照超过 90 秒时仅降低占用数字至 60% 不透明度；两种主题下均需保持可读，浮层和辅助技术可访问文本同时提供采样时间，避免仅靠透明度解释新旧。
- 点击或键盘 Enter/Space 打开，Esc/点击外部关闭，关闭后焦点返回触发控件。
- 不弹 toast、不自动展开、不播放动画；不提供自动处置按钮。
- 可见文案使用宿主本地化机制，样式与监听器跟随插件生命周期清理。

v1 验收语言为简体中文，其他宿主语言回退简体中文，不承诺完整翻译。实现时给 §3、§5–7 的状态文案建立稳定 locale key，验收覆盖读取中、不可用、未知、更新中、待采样、连续失败、运行时长、状态待确认及历史未确认。无需为 M0 先完成完整文案资产库。

### 7.4 最小脱敏规则

统计身份与显示名称分离。完整目标仅在宿主内用于当次规范化与去重；界面只接收脱敏名称、该会话内的目标编号和计数。原始值不进入插件日志、兼容登记、试用报告或持久化缓存。

| 内容 | 默认展示规则 |
|---|---|
| URL | 删除 userinfo、query 与 fragment；已确认可公开的主机名可以保留；IP、内网主机名和无法判断的地址显示“目标 #N”。路径只显示工具适配器明确允许的非敏感片段，其他片段使用省略号 |
| 本地路径 | 用户主目录替换为 `~`，工作区内使用相对路径；用户名、凭据片段及不能确认安全的目录/文件名隐藏，必要时仅显示“文件 #N” |
| 错误文本 | 仅用已验证错误类别与安全参数生成摘要，不直接截取原始输出；无法安全归类时显示“调用失败，详见会话原记录” |
| 凭据与个人标识 | 密码、密钥、token、cookie、认证头、邮箱等不作为摘要参数传入；不能确定是否安全时使用类型与目标编号 |

不同原始目标即使脱敏后同名，也保留不同目标编号，目标数按原始规范化身份统计。首版不增加“显示原文”开关；查看原始证据由用户回到宿主会话完成。验收用合成敏感样例，不把真实凭据带入测试报告。

## 8. 实现约束

### 8.1 宿主与界面职责

宿主侧负责当前会话定位、只读解析、事件关联和状态计算；界面侧只接收结构化快照并渲染。宿主与界面通信必须使用已验证的宿主扩展能力。

`host.call`、方法注册和 resources 读取仅是候选路线，未验证前不写成已存在接口。若直接通信不可用，先记录替代路线的读写位置、更新机制与清理行为，再调整实施方案；不能静默引入额外常驻服务。

快照至少含：会话身份、文件代次、请求代次、读取状态、各能力可用性、读取/采样时间及可信性、上下文快照、当前提示、历史证据。不要用一个绿色/黄色字段代替完整数据状态。

### 8.2 轮询、缓存与解析

- 当前会话可见时每 5 秒拉取一次；切换会话立即拉取。界面隐藏时暂停轮询，恢复可见时立即刷新。
- 每个视图最多等待一个有效请求；会话切换、超时和卸载使旧请求代次失效，迟到的旧响应必须丢弃。客户端停止等待不等于宿主计算已经取消，实际执行限制见下文。
- 按文件身份、mtime、size 缓存解析结果；每次请求重新评估时间相关提示，不能直接返回旧告警结果。
- 首次读取后优先增量解析追加数据；文件截断、替换时清除相关缓存并重建。持续追加时不得每 5 秒全量解压整个长会话。
- 每次刷新先检查源文件状态，不能只依赖已打开的文件句柄。文件整体删除（ENOENT）时，清除当前解析缓存、用量和提示；若宿主仍选中该会话，显示“状态不可用 · 会话文件不存在”，只有宿主明确无会话才隐藏。文件重新出现时开启新文件代次并完整重建，不复用旧 seq 去重集。权限错误与暂时不可读显示明确错误，不误当删除。
- 按 zstd 帧结构推进，具体实施路径见下文；不能仅凭压缩字节中的魔数扫描认定帧边界。
- 尾部未写完的帧保留到下次重试，不把它直接当成整个文件损坏；标明正在等待完整数据。中间损坏或未知格式影响完整性时降级，不静默吞错后声称状态正常。
- 去重键包含工作区、会话、文件代次与 seq/事件 ID。截断、替换、删除后重建时丢弃旧代次的事件索引；同文件身份下发生格式变更或 seq 回退时，先验证是否重建，无法判断则停止受影响的增量合并并降级，不直接吞掉新事件或跨代次混算任务。

**超时、重试与有界执行**

- 常规刷新超时初值 10 秒；首读及历史重建超时初值 30 秒。M0 根据 §9.3 的固定样本实测校准并登记，正式实现前必须给出有限上限。相同源文件版本的首读最多自动重试一次，之后保持加载失败，待源文件改变或用户再次启用插件后重试，不进入无限全量扫描。
- 超时后客户端释放等待状态，使旧请求代次失效，显示“状态暂不可用”；旧快照只在浮层带时间展示。常规刷新重试间隔采用 5 / 10 / 20 / 30 秒并保持 30 秒上限，首读的一次重试延迟 5 秒；成功后恢复 5 秒轮询，隐藏或卸载时停止重试。
- 宿主侧同一会话最多一个实际解析/计算任务；新请求复用同一有界任务或读取最近完成快照，不为每次超时追加后台工作。同一宿主插件实例总解析并发初值为 2，待处理会话按会话键合并且初始容量上限为 8；容量不足返回忙，不建立无界队列。以上容量由 M0 校准，调整后仍须保持明确上限。
- 底层支持取消时必须传递取消信号；不支持时，需要能终止插件自身计算的隔离执行或可中断的分段处理，并给出执行截止时间。不能仅释放客户端名额后反复启动无法结束的计算。所有截止时间只影响插件自身工作，不终止用户的工具或任务。
- M0 若无法证明有界执行和取消/恢复路线，标记为实时链路未通过；在解决前不进入依赖该链路的正式实现。验收包含永久挂起、连续超时后恢复和迟到响应。

**多窗口/多视图**

每个视图拥有独立的当前会话身份、请求代次和 UI 注册；关闭一个视图只清理其订阅。宿主对同一会话合并计算并共享只读快照，不能互相覆盖视图状态；多个宿主实例的内存状态不混用。M0 按宿主实际支持情况验证多窗口，未支持的形态写入能力限制，不默认加入随机抖动。

**zstd 帧偏移推进方案**

优先使用能返回“完整帧结束 + 实际消耗输入字节数”的解码器，按消耗的压缩字节数推进。M0 验证当前 Node 运行时是否提供此能力；`zlib.zstdDecompressSync` 能解单帧这一已有验证结果，不等于它能返回帧边界偏移。

若无此接口，采用“帧结构定界 + 单帧解压”：

1. 从已知帧起点校验 magic，读取 frame header descriptor，按标志读取可选 window descriptor、dictionary ID 和 frame content size。
2. 逐个读取 3 字节 block header；Raw/Compressed 块按 `Block_Size` 跳过载荷，RLE 块载荷为 1 字节，Reserved 类型报格式错误。
3. 读到 `Last_Block` 后，如帧头声明 checksum，再消费 4 字节；该位置就是下一帧起点。截取完整帧交给 `zlib.zstdDecompressSync` 解压并验证。
4. 任一步字节不足时保留当前帧起始偏移与尾部数据，等下次追加后重试。遇到 skippable frame 按其 magic、长度字段和载荷长度跳过，不能当作会话事件。

`Frame_Content_Size` 是**解压后的大小**，不用于计算压缩文件的下一帧偏移；有无该字段均按上述帧/块结束位置推进。格式依据：[Zstandard 官方格式规范](https://github.com/facebook/zstd/blob/dev/doc/zstd_compression_format.md)。

### 8.3 本地性与资源

- 不调用外部网络、分析服务或遥测；仅使用宿主必要的本地通信。
- “只读”约束适用于插件对会话源文件的访问，不要求宿主停止正常写入会话。
- 不修改会话、自动重试工具或终止任务。
- 插件停用或卸载后取消定时器、请求、监听器和 UI 注册；已返回的异步结果不能重新挂载 UI。

## 9. 验收标准

### 9.1 确定性回放

使用可控制的虚拟时钟与事件序列，按时间推进；每个判定时刻只能读取当时已出现的数据。至少覆盖下列用例，预期全部通过：

| 编号 | 用例 | 预期 |
|---|---|---|
| AC-01 | 同类失败 → assistant/step 事件 → 同类失败 | 触发一次连击提示 |
| AC-02 | 同工具失败 → 同工具另一目标成功 → 原类别失败 | 不触发连续两次提示；成功仅表示连击中断 |
| AC-03 | 同工具同类失败、不同目标各一次 | 合并为一条提示，显示“2 条记录 · 2 个目标” |
| AC-04 | 本机同轮 web_fetch 的 8 个 URL 失败完整序列 | 若中间无本工具成功、取消、未知或不同类别，则第二次触发并累计到 8；目标数按实际 URL 去重 |
| AC-05 | 不同工具同类失败；或同工具 A 类失败 → B 类失败 → A 类失败 | 不合并工具，不跨不同类别累计为连续两次 |
| AC-06 | 取消、未知结果、普通正文含 Error、正常的搜索无匹配 | 不误算为明确失败 |
| AC-07 | 同一失败通过两种事件报告，或同一事件重复轮询 | 只计一次 |
| AC-08 | 提示触发后成功、取消、换错误类型、轮次结束 | 按 §6.1 解除或转历史，文案不误称修复 |
| AC-09 | 任务 299 秒，文件不再变化，推进至 300 秒 | 下一次轮询触发相应提示 |
| AC-10 | 任务仅有开始记录、缺少存活确认 | 显示状态待确认，不显示仍在运行 |
| AC-11 | M0 确认无存活查询能力 | 整个版本不提供运行时长档，默认档仍能完成长任务提示验收 |
| AC-12 | 有存活查询能力但确认超时/失效 | 从运行时长档回到待确认，不继续沿用旧确认 |
| AC-13 | 长任务终态到达；宿主断连/重启 | 解除或降级，不继续累加虚假的运行时长 |
| AC-14 | 超过 300 秒后以 killed 结束的完整任务回放 | 阈值前不提示，阈值后按当时能力提示，killed 到达后解除；不提前读取终态 |
| AC-15 | 无会话、无 usage、窗口缺失、模型切换、手动/自动压缩 | 按相应规则隐藏、局部降级或等待更新 |
| AC-16 | usage 恒等式成立、不成立、字段缺失、零可检样本 | 成立才计算 totalTokens − outputTokens；其余为上下文未知，不只取 inputTokens |
| AC-17 | 快照年龄 90 秒、超过 90 秒、重新读旧快照、新快照到达 | 超过阈值仅数字降至 60% 不透明度；读取不刷新采样时间，新鲜快照恢复 |
| AC-18 | A 会话请求未返回时切到 B；A 随后返回 | B 不被旧响应覆盖 |
| AC-19 | 尾部半帧、中间损坏、格式升级、文件截断或替换 | 可恢复重试或明确降级，无崩溃、无错误正常态 |
| AC-20 | 无 content size 帧、多块帧、RLE、checksum、skippable frame、载荷内含 magic | 按实际帧结构推进，得到正确偏移，半帧不消费或丢弃 |
| AC-21 | 两类提示同时出现、提示解除后仍有历史记录 | 优先级正确，历史不继续使标题栏变黄 |
| AC-22 | 确认宿主重启，旧任务无终态且无新关联证据 | 转历史状态未确认，不持续挂黄；切换会话/隐藏不模拟重启 |
| AC-23 | 无法确认宿主周期，最近任务证据距今 29:59 → 30:00 | 跨过展示期限转历史未确认；重复读取不延长期限；取得新证据后重新判定 |
| AC-24 | 同一 jobId 重读同一开始事件、出现新的开始事件、收到歧义终态 | 先去重；新开始建立独立任务；不凭 jobId 把旧终态归给新任务 |
| AC-25 | 刷新或首读永不返回，连续超时后恢复 | 在登记时限内降级、退避恢复；旧响应无效，实际计算/排队不超上限 |
| AC-26 | 底层不支持取消，多窗口持续重试同一会话 | 宿主合并并有界执行，不因客户端释放等待而新建无界计算 |

### 9.2 真实样本试用

- 先修正现有探测脚本的连击中断、取消排除、任务计时与去重口径，保存脚本版本、样本清单和回放输出。
- 开发调试样本与验收样本分离；原三个压缩会话不再用于证明 ETA 能力，因为 v1 不含 ETA。
- 在独立样本中收集至少 20 条不同的提示实例，两类规则均需至少 5 条；一条提示的多次轮询只算一例。数量不足时标记“准确性尚未验收”，继续内部试用，不重复抽样凑数。
- 人工核验事实陈述是否与日志一致，错误事实必须修复；另由用户判断“当时是否值得查看”，目标至少 80% 认可。该目标是试用门槛，不是泛化准确率承诺。
- 另抽查至少 20 个未提示的独立任务/轮次，检查是否遗漏符合已定义规则的情况；仅评价规则覆盖，不声称能识别所有走歪任务。
- 触发率只记录为观察指标，不设“必须 ≤3%”，避免通过少报来满足验收。
- 增加提示疲劳软指标：**黄点覆盖的会话时长占比 = 当前会话在可见且可判定期间显示黄色的时长 / 该会话可见且可判定的总时长**。隐藏、切走、停用或整会话数据不可用的时间不计入分母；多条提示重叠的黄色时长只算一次。逐会话记录分子、分母与占比，汇总按总时长加权，不简单平均百分比。
- 同时记录单条提示的平均持续时长：按唯一提示实例统计已解除提示从触发到解除的时间，更新计数不新建实例；未解除提示另报数量和当前年龄，不按已解除混算。离线期间缺少真实解除时刻的实例单列，避免把重新打开界面的时间当作精确解除时间。指标仅用于本地试用验收，不新增遥测服务。
- 黄点覆盖时长占比 >30% 只触发复盘，不要求调参。结合人工认可度、提示类型、未解除提示年龄与有效观察时长，可以得出“提示有效，阈值不变”。若确需调整，可收紧对应条件或将连续失败次数改为 3 次，并重跑回放及独立验收；不自动改线上阈值，不靠少报满足指标。对始终待确认的任务先查退场规则与状态完整性。
- 试用默认按一周汇总，可判定且可见总时长不足 60 分钟标“观察量不足”；不足 5 分钟的单会话只作个案参考。这些是报告解释口径，不是新增发布硬门槛，不能因短暂 100% 黄色就判定疲劳。多窗口同时展示同一会话时统计可见时段并集，不重复累计；无法跨宿主实例去重时分实例报告，不冒充跨实例总值。

### 9.3 工程与界面

- 只读：通过插件文件访问审计确认没有向会话目录写入；同时允许宿主正常追加。对固定回放副本核对运行前后哈希。
- 本地性：检查插件的网络调用与依赖行为，确认无外部请求；宿主本地通信单独列明。
- 响应：在数据已完整可读、界面可见且处理未超时的条件下，提示触发与解除在下一轮询内可见，目标不超过 6 秒。
- 故障响应：常规请求在登记的超时上限内退出等待并显示不可用；永久挂起不能产生无界后台任务。恢复后按退避计划重新获取数据，旧代次响应不能覆盖新数据。首读单独受登记上限约束，不用正常 6 秒响应目标掩盖首读超时。
- 性能：固定一个 200 轮样本和一个不少于 10,000 个事件的大样本，并记录文件字节数、事件数、轮次、机器与运行时版本。真实样本不足时可构造结构真实且标为合成的压力样本，只用于工程验收，不替代准确性验收。覆盖大工具输出与持续追加，不只复制小事件凑数量。
- 每个性能样本分别测量冷启动首读至少 5 次、预热后缓存命中与增量追加各至少 100 次；两类轮询 CPU 时间 p95 均以 <20ms 为目标，首读墙钟耗时、峰值内存和超时次数单列。M0 据实校准首读上限，验收报告记录最终值；持续追加不阻塞 UI，不能混合大量缓存命中来掩盖追加解析变慢。
- 生命周期：连续切换会话、启停、卸载后无残留 DOM、定时器、监听器和新增 console 错误；一小时运行无持续资源增长。
- 界面：浅色/深色、小窗口、键盘操作、长错误摘要、数据未知与多提示状态均可用。

| F05 | P2 | 旧轮迟到结果被算进新轮 | 调用登记时绑定轮次，迟到结果只进历史。回归 H2 |
| F06 | P2 | seq 回退被当重复直接丢弃，成功记录丢失 | 不再丢弃：标记 `out-of-order` 并切断连击。回归 H3 |
| F07 | P2 | 同一 callId 不同 seq 重报，一次失败算两次 | 调用级终态去重。回归 H13；真实数据中 3 个会话各含 3–8 条重复终态，现只计一次 |
| F08 | P2 | 正文行首 `Error:` 被当失败 | 只认整段文本开头的 `Error:`，且必须能关联到已知调用。回归 H4 |
| F09 | P2 | usage 不校验恒等式，坏值被采纳 | 四桶必须为非负安全整数且等于 total，否则快照作废。回归 H9 |
| F10 | P2 | sessionId 可带路径跳转 | 只接受 `[A-Za-z0-9][A-Za-z0-9._-]{0,79}`，并校验 realpath 位于会话根内。回归 H11 |

**行为变化（需要知会）**：连击改为按工具独立；同一调用的重复终态只计一次；损坏帧会让快照显示「不可用 / 待采样」而不是沿用旧值。这三条都让显示更保守。

## 17. 二轮复审修复（2026-10-30，源包 8846c15e）

| 编号 | 问题 | 修复 |
|---|---|---|
| R1 | 完整性标记没到界面 | 卡片末行与浮层都显示「记录不完整」，按 `bad-json / out-of-order / short-read` 分三种说明；数值恢复不代表历史缺口消失 |
| R2 | 同一 inode 中段改写沿用旧缓存 | 字节级校验已消费前缀：每次文件变化都对 `[0, cursor)` 做 sha256 比对，不一致即开新代次；另对同尺寸 + mtime/ctime 变化直接重建。5MB 会话校验耗时 3ms |
| R3 | 合法 skippable 半帧被误判损坏 | skippable 解析也改三态；长度头或载荷不足一律 `incomplete`，不进 `integrity` |
| R4 | 重放调用登记绕过终态去重 | 调用登记幂等（同 callId 不覆盖），终态去重改用独立的 `settledCalls` 集合，先于任何状态变更 |

**仍然存在的限制（明确登记，不改称为已解决）**：
- 前缀哈希的代价是每次追加多一次 5MB 读取（实测 3ms），换来“任意位置改写可检测”。
- 文字类失败（未带 `data.error`）现在一律不计，宁可漏报也不误报；若某工具只输出文本错误，需要单独为其协议加白名单。
- 30 分钟无证据的任务转入历史（`endedBy: unconfirmed`），不伪造完成/失败。
